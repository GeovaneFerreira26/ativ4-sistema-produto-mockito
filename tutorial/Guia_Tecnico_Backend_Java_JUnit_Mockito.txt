====================================================================== 1.
OBJETIVO E ESCOPO
======================================================================

Este documento transforma a atividade em um roteiro de implementacao
backend. O objetivo e criar e testar as regras de negocio de produtos e
pedidos sem conectar a um banco de dados real.

Tecnologias exigidas pela atividade: - Java JDK 17 ou superior - Maven -
JUnit 5 (junit-jupiter) - Mockito (mockito-junit-jupiter) - IntelliJ
IDEA

Arquitetura: - Model: representa os dados do dominio. - Repository:
contrato de acesso aos dados. - Service: concentra as regras de
negocio. - Exception: representa erros especificos do dominio. - Test:
testa a camada Service com os repositories substituidos por mocks.

IMPORTANTE SOBRE OS MODULOS: A atividade nao exige dois projetos Maven
independentes. Recomenda-se um unico modulo Maven chamado
sistema-produtos-mockito, separado em: - codigo principal:
src/main/java - codigo de teste: src/test/java

Assim, o Maven compila o codigo principal e executa os testes em uma
fase separada. Os testes nao devem acessar banco, rede ou arquivos
reais.

MockitoExtension, @Mock e @InjectMocks. 3. maven-compiler-plugin:
configura a compilacao para Java 17. 4. maven-surefire-plugin: descobre
e executa os testes durante mvn test.

As dependencias JUnit e Mockito possuem scope test: ficam disponiveis
para compilar e executar testes, mas nao sao dependencias do codigo
principal.

Nao e necessario adicionar Spring Boot, driver MySQL, JPA ou banco de
dados: a atividade trabalha com interfaces e mocks, sem persistencia
real.

7.1 ProdutoService.java

Caminho: src/main/java/br/com/techstore/service/ProdutoService.java

package br.com.techstore.service;

import br.com.techstore.exception.ErroAoSalvarProdutoException; import
br.com.techstore.exception.ProdutoNaoEncontradoException; import
br.com.techstore.model.Produto; import
br.com.techstore.repository.ProdutoRepository;

public class ProdutoService {

    private final ProdutoRepository repository;

    public ProdutoService(ProdutoRepository repository) {
        this.repository = repository;
    }

    public Produto salvar(Produto produto) {

        if (produto == null || produto.getNome() == null
                || produto.getNome().isBlank()) {
            throw new IllegalArgumentException(
                    "Nome do produto e obrigatorio");
        }

        if (produto.getPreco() <= 0) {
            throw new IllegalArgumentException(
                    "Preco deve ser maior que zero");
        }

        if (produto.getQuantidade() < 0) {
            throw new IllegalArgumentException(
                    "Quantidade nao pode ser negativa");
        }

        try {
            return repository.salvar(produto);
        } catch (RuntimeException e) {
            throw new ErroAoSalvarProdutoException(
                    "Falha ao salvar o produto", e);
        }
    }

    public Produto buscarPorId(Long id) {

        Produto produto = repository.buscarPorId(id);

        if (produto == null) {
            throw new ProdutoNaoEncontradoException(
                    "Produto nao encontrado: " + id);
        }

        return produto;
    }

}

REGRAS IMPLEMENTADAS: - Produto nulo: rejeitado. - Nome nulo, vazio ou
em branco: rejeitado. - Preco menor ou igual a zero: rejeitado. -
Quantidade negativa: rejeitada. - Quantidade igual a zero: aceita. -
Repository so e chamado depois das validacoes. - Falha RuntimeException
durante salvar: convertida em ErroAoSalvarProdutoException. - Busca que
retorna null: gera ProdutoNaoEncontradoException.

7.2 PedidoService.java

Caminho: src/main/java/br/com/techstore/service/PedidoService.java

VERSAO BASE DA ATIVIDADE:

package br.com.techstore.service;

import br.com.techstore.exception.EstoqueInsuficienteException; import
br.com.techstore.exception.ProdutoNaoEncontradoException; import
br.com.techstore.model.Pedido; import br.com.techstore.model.Produto;
import br.com.techstore.repository.PedidoRepository; import
br.com.techstore.repository.ProdutoRepository;

public class PedidoService {

    private final ProdutoRepository produtoRepository;
    private final PedidoRepository pedidoRepository;

    public PedidoService(ProdutoRepository produtoRepository,
                         PedidoRepository pedidoRepository) {
        this.produtoRepository = produtoRepository;
        this.pedidoRepository = pedidoRepository;
    }

    public Pedido criarPedido(Long produtoId, int quantidade) {

        if (quantidade <= 0) {
            throw new IllegalArgumentException(
                    "Quantidade deve ser maior que zero");
        }

        Produto produto = produtoRepository.buscarPorId(produtoId);

        if (produto == null) {
            throw new ProdutoNaoEncontradoException(
                    "Produto nao encontrado: " + produtoId);
        }

        if (quantidade > produto.getQuantidade()) {
            throw new EstoqueInsuficienteException(
                    "Estoque insuficiente");
        }

        double total = produto.getPreco() * quantidade;

        Pedido pedido = new Pedido(produto, quantidade, total);

        pedidoRepository.salvar(pedido);

        return pedido;
    }

}

REGRAS IMPLEMENTADAS: - Quantidade do pedido menor ou igual a zero:
rejeitada. - Produto nao encontrado: rejeitado. - Quantidade maior que o
estoque: rejeitada. - Quantidade igual ao estoque: aceita. - Total
calculado por preco multiplicado pela quantidade. - PedidoRepository so
e chamado depois de todas as validacoes.

VERSAO MELHORADA - DESAFIO 7, CENARIO D:

Para tratar falhas do PedidoRepository com uma excecao propria,
substitua o metodo criarPedido da versao base pelo metodo abaixo e
adicione o import da ErroAoSalvarPedidoException:

import br.com.techstore.exception.ErroAoSalvarPedidoException;

public Pedido criarPedido(Long produtoId, int quantidade) {

    if (quantidade <= 0) {
        throw new IllegalArgumentException(
                "Quantidade deve ser maior que zero");
    }

    Produto produto = produtoRepository.buscarPorId(produtoId);

    if (produto == null) {
        throw new ProdutoNaoEncontradoException(
                "Produto nao encontrado: " + produtoId);
    }

    if (quantidade > produto.getQuantidade()) {
        throw new EstoqueInsuficienteException("Estoque insuficiente");
    }

    double total = produto.getPreco() * quantidade;
    Pedido pedido = new Pedido(produto, quantidade, total);

    try {
        pedidoRepository.salvar(pedido);
    } catch (RuntimeException e) {
        throw new ErroAoSalvarPedidoException(
                "Falha ao salvar o pedido", e);
    }

    return pedido;

}

IMPORTANTE: Escolha uma das versoes do metodo. A versao melhorada
substitui a versao base; nao crie dois metodos com a mesma assinatura.

O codigo-base nao trata a RuntimeException do PedidoRepository: ela se
propaga diretamente. A versao melhorada converte essa falha em
ErroAoSalvarPedidoException.

A falha de ProdutoRepository.buscarPorId tambem nao e tratada pelo
codigo-base. Se esse repository lancar RuntimeException, a excecao se
propaga e o PedidoRepository.salvar nao deve ser chamado.

8. MODULO DE TESTES - CONCEITOS E ANOTACOES
======================================================================

Os testes ficam em src/test/java, espelhando os pacotes do codigo
principal.

@ExtendWith(MockitoExtension.class): Integra o Mockito ao ciclo de vida
do JUnit 5. Sem essa extensao, as anotacoes Mockito nao serao
inicializadas automaticamente.

@Mock: Cria um objeto simulado da dependencia. O teste controla o
comportamento desse objeto.

@InjectMocks: Cria uma instancia real da classe testada e injeta nela os
mocks compativeis. Nao transforma a classe testada em mock.

when(…).thenReturn(…): Configura o retorno de um metodo do mock.

doThrow(…).when(…): Configura uma excecao a ser lancada pelo mock. E
especialmente util para metodos void.

verify(…): Confirma que uma interacao ocorreu.

never(): Confirma que o metodo nao foi chamado.

times(1): Confirma que o metodo foi chamado exatamente uma vez.

any(Classe.class): Argument matcher que aceita qualquer argumento
compativel com o tipo.

assertEquals: Compara valores esperados e obtidos.

assertThrows: Confirma que uma operacao lancou a excecao esperada.

IMPORTANTE: ProdutoService e PedidoService devem ser objetos reais nos
testes. Os repositories devem ser mocks. Mockar o proprio Service
impediria testar suas regras de negocio reais.

package br.com.techstore.service;

import br.com.techstore.exception.ErroAoSalvarProdutoException; import
br.com.techstore.exception.ProdutoNaoEncontradoException; import
br.com.techstore.model.Produto; import
br.com.techstore.repository.ProdutoRepository;

import org.junit.jupiter.api.Test; import
org.junit.jupiter.api.extension.ExtendWith; import
org.mockito.InjectMocks; import org.mockito.Mock; import
org.mockito.junit.jupiter.MockitoExtension;

import static org.junit.jupiter.api.Assertions.; import static
org.mockito.ArgumentMatchers.any; import static org.mockito.Mockito.;

@ExtendWith(MockitoExtension.class) class ProdutoServiceTest {

    @Mock
    private ProdutoRepository repository;

    @InjectMocks
    private ProdutoService service;

    @Test
    void deveSalvarProdutoComPrecoValido() {
        Produto produto = new Produto("Mouse", 49.90, 10);
        when(repository.salvar(produto)).thenReturn(produto);

        Produto resultado = service.salvar(produto);

        assertEquals("Mouse", resultado.getNome());
        assertEquals(49.90, resultado.getPreco(), 0.001);
        verify(repository).salvar(produto);
    }

    @Test
    void naoDeveSalvarProdutoNulo() {
        assertThrows(IllegalArgumentException.class,
                () -> service.salvar(null));

        verify(repository, never()).salvar(any(Produto.class));
    }

    @Test
    void naoDeveSalvarProdutoComNomeNulo() {
        Produto produto = new Produto(null, 10.0, 2);

        assertThrows(IllegalArgumentException.class,
                () -> service.salvar(produto));

        verify(repository, never()).salvar(any(Produto.class));
    }

    @Test
    void naoDeveSalvarProdutoComNomeVazio() {
        Produto produto = new Produto("", 10.0, 2);

        assertThrows(IllegalArgumentException.class,
                () -> service.salvar(produto));

        verify(repository, never()).salvar(any(Produto.class));
    }

    @Test
    void naoDeveSalvarProdutoComNomeEmBranco() {
        Produto produto = new Produto("   ", 10.0, 2);

        assertThrows(IllegalArgumentException.class,
                () -> service.salvar(produto));

        verify(repository, never()).salvar(any(Produto.class));
    }

    @Test
    void naoDeveSalvarProdutoComPrecoNegativo() {
        Produto produto = new Produto("Mouse", -10.0, 5);

        assertThrows(IllegalArgumentException.class,
                () -> service.salvar(produto));

        verify(repository, never()).salvar(any(Produto.class));
    }

    @Test
    void naoDeveSalvarProdutoComPrecoIgualAZero() {
        Produto produto = new Produto("Mouse", 0.0, 5);

        assertThrows(IllegalArgumentException.class,
                () -> service.salvar(produto));

        verify(repository, never()).salvar(any(Produto.class));
    }

    @Test
    void deveAceitarPrecoMinimoPositivo() {
        Produto produto = new Produto("Mouse", 0.01, 5);
        when(repository.salvar(produto)).thenReturn(produto);

        Produto resultado = service.salvar(produto);

        assertEquals(0.01, resultado.getPreco(), 0.001);
        verify(repository).salvar(produto);
    }

    @Test
    void naoDeveSalvarProdutoComQuantidadeNegativa() {
        Produto produto = new Produto("Mouse", 10.0, -1);

        assertThrows(IllegalArgumentException.class,
                () -> service.salvar(produto));

        verify(repository, never()).salvar(any(Produto.class));
    }

    @Test
    void deveAceitarProdutoComEstoqueZerado() {
        Produto produto = new Produto("Mouse", 10.0, 0);
        when(repository.salvar(produto)).thenReturn(produto);

        Produto resultado = service.salvar(produto);

        assertEquals(0, resultado.getQuantidade());
        verify(repository).salvar(produto);
    }

    @Test
    void deveBuscarProdutoExistente() {
        Produto produto = new Produto("Mouse", 49.90, 10);
        when(repository.buscarPorId(1L)).thenReturn(produto);

        Produto resultado = service.buscarPorId(1L);

        assertSame(produto, resultado);
        verify(repository).buscarPorId(1L);
    }

    @Test
    void deveLancarExcecaoQuandoProdutoNaoForEncontrado() {
        when(repository.buscarPorId(99L)).thenReturn(null);

        assertThrows(ProdutoNaoEncontradoException.class,
                () -> service.buscarPorId(99L));

        verify(repository).buscarPorId(99L);
    }

    @Test
    void deveLancarErroQuandoRepositoryFalharAoSalvar() {
        Produto produto = new Produto("Teclado", 129.90, 5);

        doThrow(new RuntimeException("Falha na conexao"))
                .when(repository).salvar(any(Produto.class));

        assertThrows(ErroAoSalvarProdutoException.class,
                () -> service.salvar(produto));

        verify(repository).salvar(produto);
    }

}

    void deveLancarExcecaoQuandoEstoqueForInsuficiente() {

        when(produtoRepository.buscarPorId(1L)).thenReturn(produto);

        assertThrows(EstoqueInsuficienteException.class,
                () -> service.criarPedido(1L, 11));

        verify(produtoRepository).buscarPorId(1L);
        verify(pedidoRepository, never()).salvar(any(Pedido.class));
    }

    @Test
    void deveAceitarPedidoComQuantidadeIgualAoEstoque() {
        Produto produto = new Produto("Mouse", 49.90, 10);
        when(produtoRepository.buscarPorId(1L)).thenReturn(produto);

        Pedido pedido = service.criarPedido(1L, 10);

        assertEquals(499.00, pedido.getValorTotal(), 0.001);
        verify(pedidoRepository).salvar(any(Pedido.class));
    }

    @Test
    void devePropagarFalhaDoProdutoRepositorySemSalvarPedido() {
        when(produtoRepository.buscarPorId(1L))
                .thenThrow(new RuntimeException("Falha na consulta"));

        assertThrows(RuntimeException.class,
                () -> service.criarPedido(1L, 2));

        verify(pedidoRepository, never()).salvar(any(Pedido.class));
    }

    @Test
    void devePropagarFalhaDoPedidoRepositoryNaVersaoBase() {
        Produto produto = new Produto("Mouse", 49.90, 10);
        when(produtoRepository.buscarPorId(1L)).thenReturn(produto);

        doThrow(new RuntimeException("Falha na conexao"))
                .when(pedidoRepository).salvar(any(Pedido.class));

        assertThrows(RuntimeException.class,
                () -> service.criarPedido(1L, 2));

        verify(pedidoRepository).salvar(any(Pedido.class));
    }

    /*
     * Este teste e para a VERSAO MELHORADA do PedidoService,
     * que captura RuntimeException e lanca ErroAoSalvarPedidoException.
     * Nao execute simultaneamente com o teste de propagacao acima,
     * pois os dois representam implementacoes diferentes.
     */
    @Test
    void deveConverterFalhaAoSalvarPedidoNaVersaoMelhorada() {
        Produto produto = new Produto("Mouse", 49.90, 10);
        when(produtoRepository.buscarPorId(1L)).thenReturn(produto);

        doThrow(new RuntimeException("Falha na conexao"))
                .when(pedidoRepository).salvar(any(Pedido.class));

        assertThrows(ErroAoSalvarPedidoException.class,
                () -> service.criarPedido(1L, 2));

        verify(pedidoRepository).salvar(any(Pedido.class));
    }

}

ATENCAO AOS DOIS TESTES DE FALHA DO PEDIDOREPOSITORY: O teste
devePropagarFalhaDoPedidoRepositoryNaVersaoBase espera RuntimeException
e corresponde ao PedidoService original. O teste
deveConverterFalhaAoSalvarPedidoNaVersaoMelhorada espera
ErroAoSalvarPedidoException e corresponde ao Service alterado no
desafio.

Nao mantenha os dois testes ativos ao mesmo tempo. Se escolher a versao
melhorada, remova ou desative o teste da versao base. Se escolher a
versao base, remova ou desative o teste da versao melhorada.

12. DIFERENCA ENTRE when/thenReturn E doThrow
======================================================================

Para metodos que retornam valor:

when(repository.buscarPorId(1L)).thenReturn(produto);

Quando buscarPorId(1L) for chamado, o mock devolvera o produto
configurado.

Para simular uma excecao:

when(repository.buscarPorId(1L)) .thenThrow(new
RuntimeException(“Falha”));

Para metodos void:

doThrow(new RuntimeException(“Falha”))
.when(pedidoRepository).salvar(any(Pedido.class));

Nao e valido usar when(pedidoRepository.salvar(…)).thenReturn(…), pois
salvar retorna void e nao possui valor para retornar.

DIFERENCA ENTRE ARGUMENTO ESPECIFICO E any():
when(repository.salvar(produto)).thenReturn(produto): configura o mock
para a chamada com aquele objeto/argumento especifico, conforme as
regras de igualdade do Mockito.

doThrow(…).when(repository).salvar(any(Produto.class)): configura o mock
para lancar excecao quando salvar receber qualquer objeto do tipo
Produto.

Use argumento especifico quando o teste depende de uma chamada com
aquele dado. Use any() quando o comportamento deve valer para qualquer
argumento do tipo indicado.

15. BOAS PRATICAS E PONTOS DE ATENCAO
======================================================================

1.  Um teste deve validar um cenario principal por vez.
2.  Os nomes devem explicar o comportamento esperado.
3.  Use Arrange, Act e Assert:
    -   Arrange: preparar objetos e configurar mocks.
    -   Act: executar o metodo do Service.
    -   Assert: conferir retorno ou excecao.
4.  Use verify para confirmar interacoes.
5.  Use never para comprovar que o repository nao foi chamado em caso de
    erro.
6.  Nao mockar o Service que esta sendo testado.
7.  Nao conectar banco real nos testes unitarios desta atividade.
8.  Configure apenas os comportamentos necessarios em cada teste.
9.  Use assertEquals com tolerancia ao comparar double.
10. Mantenha os testes independentes entre si.
11. Nao use dados de um teste em outro por estado compartilhado.
12. Nao confunda teste unitario de Service com teste de integracao de
    Repository.

OBSERVACAO SOBRE VALORES MONETARIOS: A atividade usa double para
simplificar o exercicio. Em sistemas comerciais reais, BigDecimal
costuma ser mais adequado para representar valores monetarios e evitar
problemas de precisao binaria. Essa melhoria nao e necessaria para
reproduzir o codigo-base solicitado.

OBSERVACAO SOBRE PERSISTENCIA: As interfaces Repository deste exercicio
nao possuem implementacao concreta. Isso e intencional para o teste
unitario com Mockito. Em uma aplicacao real, uma implementacao seria
responsavel por persistir e consultar dados, e precisaria de testes de
integracao separados.

17. LIMITES DO QUE OS TESTES COM MOCKITO COMPROVAM
======================================================================

A afirmacao de que 18 testes passando garantem funcionamento perfeito
com o banco de producao esta incorreta.

Os testes apresentados verificam as regras de negocio dos Services
usando repositories simulados. Eles ajudam a provar que: - O Service
valida entradas. - O Service calcula o total do pedido. - O Service toma
decisoes corretas diante dos retornos configurados. - O Service reage a
falhas simuladas. - As interacoes com os repositories ocorrem ou deixam
de ocorrer conforme esperado.

Eles nao comprovam: - Que uma implementacao real de Repository esta
correta. - Que a conexao com o banco funciona. - Que tabelas, colunas e
relacionamentos estao configurados corretamente. - Que consultas SQL ou
operacoes ORM funcionam. - Que transacoes e concorrencia se comportam
corretamente em producao.

Para aumentar a confiabilidade, o projeto real tambem precisaria de
testes de integracao com a implementacao concreta do Repository e um
banco de teste. Podem ser necessarios testes de API, contrato, seguranca
e desempenho, conforme o escopo do sistema.
